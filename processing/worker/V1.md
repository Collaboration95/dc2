# Finite V1 encoder

The V1 worker container runs:

```sh
python -m processing.v1_worker --deadline-epoch "$WORKER_DEADLINE_EPOCH" \
  --name "$WORKER_TASK_NAME" --max-empty-polls 2
```

`--deadline` and `--cloud-deadline` alias `--deadline-epoch`;
`--empty-polls` aliases `--max-empty-polls`. Supply an absolute future Unix
second deadline within 3600 seconds. The essential parent process uses the
existing process watchdog. Its child encodes at most one attempt; there are no
concurrent encodes, idle respawns or automatic starts. It exits after two empty
20-second long polls by default, or after at most 25 handled messages. SIGTERM stops further claims and drains
the active attempt; repeated signals cancel it. The watchdog bounds startup,
blocked SDK calls, drain, SQL teardown and forced termination. A container exit
must collect descendants, as expected by the essential Fargate container model.

Configuration:

- `PROCESSING_WORK_QUEUE_URL` (or `WORK_QUEUE_URL`) selects the work queue.
- `AWS_REGION` selects the queue region, falling back to `PROCESSING_MINIO_REGION`.
- Existing `PROCESSING_POSTGRES_DSN`, database TLS/CA, storage, lease/heartbeat and
  FFmpeg settings remain owned by Processing. The V1 connection uses
  `processing.database.v1_connect_args` to verify SQL TLS.
- On ECS use `PROCESSING_STORAGE_CREDENTIAL_MODE=ecs`. S3 reads and output writes
  use the existing native container credential provider. SQS installs only the
  native container provider, bypassing profile/static/IMDS credential fallbacks.
- Local emulation explicitly uses `SQS_ENDPOINT_URL` (alias
  `PROCESSING_SQS_ENDPOINT_URL`) with localhost/127.0.0.1/moto/localstack, dummy
  queue credentials, local storage credentials and database TLS opt-out.

The image needs the Processing package, media_engine, contracts, delivery,
boto3/botocore, minio, SQLAlchemy/asyncpg, FFmpeg and FFprobe. The entrypoint does
not import Redis or RQ. `processing.worker.__main__`, tasks.process_attempt and
cloud.finite_worker_class remain legacy-only entries for frozen regression tests.

Canonical `contracts.v1.Envelope` validation runs before claim. The Processing
messaging claim binds the work owner, asset, source, job and attempt to durable
accepted SQL state under its claim transaction. Only that accepted Claim reaches
SourceStore. The native S3 GET pins `version_id`; the response version, streamed
byte count and SHA256 must match. No HTTP source grants or Media callback occurs.

The existing Supervisor renews SQL authority and SQS visibility together. Either
uncertainty cancels download/encoding/upload and prevents completion. Immediately
before completion the worker renews again, then calls only
`processing.messaging.finish`. That API commits fenced domain state plus the
Processing result outbox. A separate Processing control/repair publisher sends
the result; this worker has no result-send call or queue producer permission.
Receipt deletion happens only after finish returns a committed success. A lost
delete response is safe to redeliver.

A message whose claim returns nothing is deleted only when durable state proves it
dead (`processing.messaging.work_disposition`: job deleted or cancelled, a newer
attempt, or an attempt that is already claimed or terminal). The task then keeps
polling, so leftovers from repair re-sends, cancels and retries never spend it.
Malformed messages, identity/source mismatches and rows SQL cannot vouch for stay
unacknowledged, also without ending the task; the queue redrive policy quarantines
them. A reused task name (`TaskBindingError`) fails the task with exit 1 instead,
because it would reject every message.

The launch controller owns the global three-task cap and ambiguous reservations.
Task names are supplied by that controller. Durable task/attempt binding belongs
to the Processing claim/messaging API, for terminal-event recovery. Local fake
checks do not establish Fargate task residency or genuine AWS recovery evidence.
The shared integration runtime owner runs the single real PostgreSQL/S3/SQS and
short FFmpeg check; helpers must not start duplicate stacks or encodes.
