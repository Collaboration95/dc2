Audit date: 26 October 2026. Source: `76282d3b5a141f6548056f2506f9d5aff0742692` (`76282d3`), in the `dc2-rescue` worktree. Read `FEEDBACK.md` first. This audit changes only this file; application, infrastructure, workflows, deck and report remain review inputs. No commit was made.

The principal problem is insufficient design detail and traceability in the presented views. Much of the material exists in the report, but several report figures are also too abstract to meet the written request for entities, schemas and class/object interactions. SAST and DAST exist: describing either as wholly missing would be inaccurate. Their placement, limits and failure policies need to be made explicit.

## Method and reference conventions

- Parsed every `<section>` in `site/deck.html` in document order: **68 sections**, of which 1–47 are the main talk and 48–68 are backup. Slide numbers below always mean section position, not a guessed PDF page, section heading or `Bxx` label. Read each section's speaker notes separately from its visible content.
- Inspected all 11 `site/assets/img/*.svg` files, including Mermaid `foreignObject` labels. **Only the two ER SVGs are actually embedded in this deck**, both on slide 65. Other diagrams in slides are inline HTML/SVG; an asset's existence is not evidence that the audience saw it. The class-model PNG and report AWS-topology PNG were also inspected visually.
- Inspected the report source headings, relevant passages, figure references and relevant diagram sources. `R30`, `R34`, etc. below expand to full pinned file links in the reference list; every report citation gives a heading and source line. Figure names refer to repository filenames, not guessed rendered figure numbers.
- Extracted both course PDFs with `pdftotext -layout`, preserving page boundaries. Extracted the DOCX's `word/document.xml` paragraphs and table cells. Template paragraph numbers below count all body `w:p` elements, including empty paragraphs and table cells; they are reproducible extraction locators, not Word page numbers.
- Used local Git history for the named DAST branches. All live GitHub reads used authenticated `gh` CLI (`run list`, `run view`, `workflow list`); no GitHub connector, browser, direct HTTP API, checkout, fetch, workflow dispatch or cloud operation was used.
- Source configuration, dated run evidence and actual presentation delivery are separate. This audit did not observe the talk, inspect the assessor's PDF bytes or establish which backups were opened. Notes and a successful scanner job do not establish what the assessor saw or a clean security posture.
- Verdicts: **absent** = the requested artifact/detail is missing; **weak** = present but insufficient; **wrong** = conflicts with source or misstates its scope; **covered-but-not-presented** = materially covered in the report/source but omitted from the main deck. Where the two artifacts differ, the verdict names each separately. Effort is editorial/design effort unless explicitly marked **CODE**, with S = a focused correction, M = one or several new views, L = substantial design/implementation and evidence work.
