### Draft: case A, upload/process/play

Reservation commits an `UploadReservation` keyed by owner/request identity, then returns an exact-key presigned POST. The client sends bytes directly to S3. Finalize reads the owned reservation, handles replay, and verifies the object without holding a SQL row lock: HEAD identifies a VersionId, and a GET of that version verifies size, SHA-256 and content signature. A later adoption transaction locks and rechecks the reservation, saves its version/finalized timestamp, creates the `Asset`, and stages the submit command. The version pin for this upload lives on `UploadReservation`; it does not create a separate `SourceVersion`. Errors or expiry prevent adoption, and replay returns the existing Asset without another submit. Embed `W3-03`, `06a`, `06` and `24`. ## Corrections to existing §34 statements

- “No committed message is lost” overstates the publish mechanism. State durable SQL intent, at-least-once publication, retained replay and repair; operation depends on future successful relay invocations. `delivery/sql.py` explicitly reserves/commits/sends/fences and may replay uncertain sends. [Mechanism](https://github.com/Collaboration95/dc2/blob/76282d3/delivery/sql.py#L58).
- The Launch table currently implies dispatch knows duration/1080p. Split `emit_state/work_lane` size/history routing from executor `check_probe` duration/source-height admission. “1080” means source height, not maximum dimension. [Policy](https://github.com/Collaboration95/dc2/blob/76282d3/processing/short_lane.py#L81).
- `_retry_locked` does not itself acquire the guard/root locks: `handle_command` or `retry_job` owns them before calling it. [Command path](https://github.com/Collaboration95/dc2/blob/76282d3/processing/messaging.py#L232), [direct path](https://github.com/Collaboration95/dc2/blob/76282d3/processing/messaging.py#L308).
- “The job is never re-queued automatically” needs a scenario qualifier: expiry/error waits for owner retry, but the explicit live `NotAdmitted` redirect queues a new Attempt automatically. [Redirect](https://github.com/Collaboration95/dc2/blob/76282d3/processing/messaging.py#L412).
- Distinguish command ACK after inbox/domain/outbox commit from encoder work ACK after a durable outcome/SQL-proved stale, and result ACK after Media inbox/projection commit. The encoder stages result outbox; a relay sends it. [Command](https://github.com/Collaboration95/dc2/blob/76282d3/processing/handlers.py#L55), [work](https://github.com/Collaboration95/dc2/blob/76282d3/processing/worker/sqs.py#L343), [result](https://github.com/Collaboration95/dc2/blob/76282d3/media/messaging.py#L16).
