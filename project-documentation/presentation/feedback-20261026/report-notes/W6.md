## Draft replacement: logical view and dependencies

FlickPond has two business services, Media and Processing, with separate HTTP integrations. `HttpApi` routes `/api/media/*` to `MediaApi` and `/api/processing/*` to `ProcessingApi`. The `GatewayAuthorizer` configuration invokes the Media-owned `MediaAuthorizer` for protected routes. These logical names and their Python entrypoints are defined by the [handler map](https://github.com/Collaboration95/dc2/blob/76282d3/scripts/aws/v1/definitions.py#L283), [integrations](https://github.com/Collaboration95/dc2/blob/76282d3/scripts/aws/v1/definitions.py#L1560) and [route definitions](https://github.com/Collaboration95/dc2/blob/76282d3/scripts/aws/v1/definitions.py#L1602).

Media separates its HTTP API, command relay and result consumer into `MediaApi`, `MediaRepair` and `MediaResults`. Processing separates `ProcessingApi`, `ProcessingCommands`, `ProcessingRepair`, `ProcessingLauncher`, `ProcessingShortEncoder` and the finite Fargate worker. The worker container invokes `processing.v1_worker`, which enters the finite worker implementation and uses `processing.worker.sqs` for queue work. These components belong to their service; they do not become additional business services. ## Draft replacement: AD-09 identity explanation

`GatewayAuthorizer` is a **Lambda REQUEST authorizer**, configured for HTTP API payload v2 and simple boolean responses, with identity source `$request.header.Cookie` and result TTL **0**. It invokes `MediaAuthorizer`. The authorizer requires exactly one `access_token` cookie, verifies the HS256 JWT with required `sub`, `exp` and `iat` claims, then looks up the current User in Media SQL. Current `user` and `operator` roles both map to contract role `publisher`; operator privilege is checked again by Media's current-user dependency. Missing users, invalid cookies and unsupported roles fail closed. [Configuration](https://github.com/Collaboration95/dc2/blob/76282d3/scripts/aws/v1/definitions.py#L1529), [cookie parsing and lookup](https://github.com/Collaboration95/dc2/blob/76282d3/media/authorizer.py#L23), [role mapping](https://github.com/Collaboration95/dc2/blob/76282d3/media/authorizer.py#L13), [JWT verification](https://github.com/Collaboration95/dc2/blob/76282d3/media/services/security.py#L48).

Success returns `isAuthorized` and Actor context containing `schema_version`, `integration`, `owner_id` and `role`. `GatewayAdapter` reads trusted `requestContext.authorizer.lambda`, removes client `x-owner-id` and `x-role`, preserves cookies, and injects `request.state.actor` and `gateway_v1`. Each API runs its own adapter instance, shown inside that API component compartment: [Media instance](https://github.com/Collaboration95/dc2/blob/76282d3/media/lambda_handler.py#L14), [Processing instance](https://github.com/Collaboration95/dc2/blob/76282d3/processing/lambda_handler.py#L13). The trust boundary depends on restricted Lambda invocation: the authorizer/API resource policies allow the Gateway service only for the configured HttpApi source ARN and account. ## Draft addition: result replay is not always a conflict

`MediaInbox` first deduplicates by message UUID and canonical body hash. Replaying the same message and body performs no projection mutation; reusing its UUID for different content raises `MessageConflict`. A new message UUID then reaches projection checks. The example concerns schema-valid normal results for a live Asset that pass owner/job/source and output checks. `apply_result()` performs those checks before calling `validate_transition()`. With stored `state_version=3`, a v2 result is ignored, identical semantic content at v3 is ignored, and **different content at v3 is rejected**. The semantic hash excludes `message_id`. A higher version must still pass owner/source/job and attempt/transition checks; it is not automatically accepted. Inbox and projection mutation share a transaction, and failures roll back inbox acceptance and are reported as batch item failures. These are versioned state snapshots for an eventually consistent local read model, not an event-sourced history. [Inbox](https://github.com/Collaboration95/dc2/blob/76282d3/delivery/sql.py#L18), [version/attempt fences](https://github.com/Collaboration95/dc2/blob/76282d3/media/projections.py#L36), [identity/source validation](https://github.com/Collaboration95/dc2/blob/76282d3/media/projections.py#L69), [atomic application](https://github.com/Collaboration95/dc2/blob/76282d3/media/messaging.py#L16), [batch failure handling](https://github.com/Collaboration95/dc2/blob/76282d3/delivery/sqs.py#L112).
