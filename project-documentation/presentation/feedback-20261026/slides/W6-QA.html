An identical replay is ignored; conflicting v3 is rejected

Configured dc2-live · Main 76282d3 · source onlyS19
S19 · W6 integration fragment
  • Point to the first gate: message identity. Same message_id and same canonical body hash returns False without projection mutation. Same ID with a different body raises MessageConflict: delivery/sql.py:18. This is application SQL inbox dedupe, not SQS FIFO dedupe.
  • For a NEW message_id, apply_result checks owner, asset, job and immutable source before version transition checks: media/projections.py:69. Given stored v3, v2 is ignored; a new message ID with identical semantic v3 is also ignored; DIFFERENT content at v3 is rejected. The semantic hash excludes message_id: media/projections.py:36.
  • Higher versions still require consistent attempt identity/order and permitted terminal/regression behavior. The figure does not imply every v4 is accepted: media/projections.py:53. Deleted assets dominate late non-cancel results: media/projections.py:83.
  • MediaInbox plus projection mutation commit together; on exception the inbox insert rolls back and the batch adapter returns an item failure: media/messaging.py:16; delivery/sqs.py:79. Full versioned result snapshots form an eventually consistent local read model, not an event-sourced log.
