Level 2 / Explain the design

Show the design, then name the evidence boundary

Logical. Media owns accounts, assets, upload identity and owner reads; Processing owns jobs, attempts, leases and encoding. SQL outbox/inbox makes publication recoverable with idempotent duplicates. The gateway passes trusted owner identity, so Processing never accepts a forged owner header.

Physical (dc2-live). API Gateway, Lambda, SQS, S3, CloudFront; short encodes on Lambda, others on finite Fargate. Each service has its own Aurora cluster (AD-29): isolated capacity and failure, but one region, not HA.

Boundaries. 629119c has a hosted CI/CD receipt and upload-to-playback smoke; c7c489c (21 October) added the certifi fix. A smoke proves one path only. Keep the six-clip cap-2 miss and cap-3 pass visible; long Fargate clips wait about 37 s against 20 s. The V2-live nine-clip run at fixed cap 3 (2.26 jobs/min) is separate. Level 2 / Explain the design

Rehearse the live path and its fallback

Prepare an approved owner account (verify login), a small clip under the 100 MiB limit (short-lane clips finish on Lambda), a prepared folder and one job ID. Start the environment early; a manifest is not a live check. Never show a password, token or signed URL.

  1. Maya submits the prepared folder with the Publisher CLI; show per-file outcomes, keep one accepted job ID.
  2. Open the browser as the same owner; status reaches done; play the MP4 (HLS only if present).
  3. Jules points to the public API contract and CLI boundary.
  4. Sam uses a saved, source-labelled capacity or release receipt. Never trigger a scale or failure experiment live.

Use a failed job only if prepared; retry uses the stored source. If anything stalls, say what failed and switch to a pre-captured recording or screenshots of the same environment and source, else the retained receipt, labelled recorded, not live. No recording identifier attached: check access.

Keep the fallback honest

Label each backup with environment and source revision; a screenshot does not prove the live system is available.

Level 3 / Defend the details

Questions to expect and facts to confirm

Why split Media and Processing?
Media owns identity and assets; Processing owns jobs and attempts. Separate contracts allow independent capacity and releases, at the cost of more messaging.
Does the platform prove the scalability target?
Partly. AWS V1 six clips: 2.347× at three workers (target 2.1×, met), 1.449× at two (1.6×, missed); no 30-clip run; the fixed-cap-3 V2-live run is no comparison.
Is the system highly available?
No proof. One region; single-instance Aurora clusters isolate capacity and failure between services but give no replica failover. Claim no regional or database HA.
Why one Aurora cluster per service, and how was it done?
A shared cluster shared capacity and failure despite separate roles (AD-29). Media kept the original; Processing got a copy-on-write clone; each dropped the other's database; both pause at 0 ACU. Rehearsed on a throwaway stack, snapshot kept, CD run 39644028238. Cost: a second cluster's storage and wake.
What is the Lambda short lane, and what did it fix?
Clips ≤60 s, ≤64 MiB, ≤1080p go to a Lambda container (3008 MB, 900 s, concurrency 2); others to finite Fargate (cap 3). It removed the queue wait (0.26 s vs 32.6 s; $0.0003 vs $0.0021 per encode; 0 failures, table above) but 35–80 s per job is unexplained, so 20 s is still missed.
How is security checked, and what is left open?
CodeQL, Trivy per image, ZAP authenticated DAST, Ruff security, gitleaks; SARIF to code scanning, Dependabot on. 22 October: 12 High CodeQL alerts dismissed with reasons. Open: ZAP low/info on OpenAPI pages; accepted CVE-2025-52290 (ffmpeg).
What did Team 17 inherit, and what did it add?
Inherited: FFmpeg processing, HLS, worker replicas, basic CI. Added: Media/Processing split, contracts, Publisher, AWS platform and pipeline, Lambda short lane, per-service databases, security boundaries, experiments.
How much did each person work, and who authored each design?
The ledger allocates 33 person-days / 264 hours equally: 11 days / 88 hours each (8 h/day). Not timesheets; each person confirms; do not infer authorship from commits or agent activity. Project 1 membership statements have a provenance tension.
What are the known limitations?
AISS-01..05. 01 performance misses (20 s end-to-end on both lanes, about 37 s long-clip queue wait, two-worker 1.449×, no 30-clip run). 02 public execute-api URL reachable beyond CloudFront, no WAF. 03 image-only rollback; schema never restored. 04 operations: broad CD role, no staging or reviewer gate, 13 alarms notify nobody, 7-day logs. 05 not established: lost-queue-entry timing, duplicate-output check after worker kill, restore drill, Publisher effort, actual spend.
