Reference / Language without the fog

What do these words mean?

A short definition, then the specific meaning in FlickPond.

ACU · Aurora Capacity Unit

A unit used to express Aurora Serverless compute capacity; it bundles memory and associated processing/network resources.

Here: Zero ACU means the recorded database compute paused. It does not mean storage is free or every future request will be instant.

See it in the project →
Adapter

Code that translates one interface into another while keeping most business logic independent of the surrounding system.

Here: The Gateway adapter translates an AWS HTTP API event into a request the FastAPI application can handle.

See it in the project →
Aggregate

A group of related domain state whose consistency rules are managed together.

Here: An owned asset and a processing job are separate centers of consistency, in different services.

See it in the project →
Alembic / migration

A tool and ordered change scripts for evolving relational database structure.

Here: Each owner has its own migration history. Released migration bytes are preserved; rolling back an image does not undo a migration.

See it in the project →
API Gateway

The AWS service that receives HTTP requests and invokes the configured application integrations and authorization checks.

Here: The HTTP API routes /api/media and /api/processing to their respective Lambda handlers.

See it in the project →
API · Application Programming Interface

A contract through which one program asks another to do something or return data.

Here: The browser and Publisher use public HTTP endpoints rather than database or queue credentials.

See it in the project →
Artifact

A concrete output of a build or verification process, such as an image or test report.

Here: CD needs source-matched evidence and immutable image identity, not merely a tag saying latest.

See it in the project →
ASGI

The asynchronous Python interface between a web server or adapter and an application.

Here: FastAPI speaks ASGI; a small adapter connects it to API Gateway payload-v2 events.

See it in the project →
Asset / job / attempt

The owned resource, the work requested for it, and one execution of that work.

Here: A failed job can be retried from the same source with a new attempt and lease.

See it in the project →
Aurora auto-pause / resume

Reducing idle database compute capacity to zero, then resuming it when demand returns.

Here: A retained observation on daee44b reached 0.0 ACU about 56 minutes after the last upload. That is one point-in-time pause observation, not a monthly cost or resume-latency measurement.

See it in the project →
Authentication / authorization

Authentication identifies the caller. Authorization decides what that caller may do to a particular resource.

Here: A valid Arun session must still be denied access to Maya’s video.

See it in the project →
Availability Zone

An isolated location within an AWS region used to place infrastructure.

Here: The VPC spans two zones, but the baseline still has one Aurora instance; subnet distribution alone is not a high-availability proof.

See it in the project →
bcrypt

A password-hashing algorithm designed to make checking password guesses deliberately expensive.

Here: Media stores password hashes and verifies them; it does not need to recover a user’s original password.

See it in the project →
Bounded context

A domain boundary within which terms, rules and data ownership have a consistent meaning.

Here: Media owns content and user-facing reads; Processing owns attempts and execution.

See it in the project →
Branch coverage

A measure of whether alternative decision outcomes were exercised, such as both true and false paths of a condition.

Here: Raw branch targets make untested recovery and authorization decisions more visible than a statement-only number.

See it in the project →
CI / CD

Continuous integration automates checks when code changes. Continuous delivery/deployment automates preparing or applying a verified release.

Here: GitHub Actions selects verification lanes, and successful eligible Main CI can trigger delivery to dc2-live.

See it in the project →
CloudFormation

AWS infrastructure definitions that create or update a related set of resources as a stack.

Here: Python renders the template used for the platform; the persistent stack is named dc2-live.

See it in the project →
CloudFront

AWS’s content delivery network, which serves and forwards web requests close to clients.

Here: It serves the static frontend from private S3 and forwards /api requests to the HTTP API.

See it in the project →
CloudWatch

AWS’s service for logs, metrics, dashboards and alarms.

Here: Recorded task activity, database capacity and selected alarms help explain operations. A past OK alarm snapshot is not continuous proof.

See it in the project →
Cold start / task startup

Initialization delay when a compute process or container starts before it can perform useful work.

Here: The historical queue-wait measurement includes Fargate task creation-to-start delay. It is not a direct measurement of Python initialization time.

See it in the project →
Container image / container

An image is a packaged filesystem and runtime configuration. A container is an execution of that package.

Here: Media, Processing and the encoder have three images; both Lambda and Fargate can run image-packaged code.

See it in the project →
Contract

The agreed shape and meaning of communication between components.

Here: OpenAPI describes HTTP operations; contracts/v1.py defines trusted actors, source descriptors and message envelopes.

See it in the project →
DAST / SAST

Dynamic application security testing sends requests to a running application. Static application security testing analyzes code without executing the target application.

Here: ZAP provides bounded DAST. Ruff security lint checks source patterns; it is not full data-flow SAST. Sonar is unconfigured.

See it in the project →
DDD · Domain-driven design

Organizing software around the domain’s language, responsibilities and consistency rules.

Here: The important decision is who owns assets versus processing attempts, not merely which folder holds a class.

See it in the project →
Dead-letter queue / DLQ

A queue holding messages that repeatedly failed normal consumption so they can be inspected or handled deliberately.

Here: Each standard work/command/result queue has a corresponding DLQ. A DLQ is not automatic proof that the business operation recovered.

See it in the project →
Digest / configuration ID

A cryptographic identity for particular image bytes or image configuration, rather than a mutable label.

Here: Registry manifest digests must be bound to the configurations that scans actually checked.

See it in the project →
ECR · Elastic Container Registry

AWS’s registry for storing container images.

Here: It holds the Media, Processing and worker builds used by Lambda and Fargate.

See it in the project →
ECS / Fargate

ECS coordinates container tasks. Fargate provides the managed compute on which those tasks run.

Here: Finite worker tasks run FFmpeg up to a bounded concurrency cap; there is no permanently running encoder service.

See it in the project →
EventBridge

An AWS event-routing and scheduling service.

Here: Wake events and scheduled fallback/repair work help the launcher and recovery handlers run; SQL still owns the durable job state.

See it in the project →
Eventual consistency / projection

A derived view can lag the authoritative state until an update arrives. A projection is that derived view.

Here: Media maintains a local ProcessingProjection from result snapshots instead of reading Processing’s database on each list request.

See it in the project →
FastAPI / Pydantic

A Python API framework and a library for validating structured data.

Here: They define and validate HTTP inputs/outputs; domain transactions and ownership checks still need explicit code.

See it in the project →
Fencing

Checking an authority token or version so an obsolete actor cannot overwrite current state.

Here: A late worker must still hold the current attempt’s valid lease before its finish operation can succeed.

See it in the project →
FFmpeg / FFprobe

Tools for transforming media and inspecting media metadata.

Here: They provide the actual encoding/probing engine; the Python platform surrounds them with ownership, orchestration and recovery.

See it in the project →
HLS / MP4

HLS streams media using a playlist and segments. MP4 is a media file/container format.

Here: The project produces playable MP4 and best-effort adaptive HLS; HLS is not guaranteed for every source.

See it in the project →
IAM / least privilege

AWS identity and access management; least privilege means giving an identity only the permissions it needs.

Here: A worker role, a Lambda role and the GitHub deployment role serve different purposes and have different permissions.

See it in the project →
Idempotency

Recognizing a repeated operation so repeating one intent does not accidentally create a new logical effect.

Here: Stable request/message identities protect uncertain retries. A new confirmed publish is a new user intent, even for identical bytes.

See it in the project →
JWT / session cookie

A signed token containing claims, carried here in an HTTP cookie to represent a login session.

Here: Media verifies the token and current user; Processing receives the trusted actor instead of the signing secret.

See it in the project →
Lambda / alias

Lambda runs event-driven functions. An alias is a stable name pointing to a published function version.

Here: The live alias is moved during owner release, with candidate checks and a restore path.

See it in the project →
Lease / heartbeat

A temporary right to perform work, periodically renewed while the worker remains healthy.

Here: Processing’s database clock, attempt identity and token decide whether a worker may still finish.

See it in the project →
Migration compatibility

Whether old and new application versions can safely use the database during a release window.

Here: The release guard rejected changed historical migration bytes. The fix restored those bytes instead of disabling the guard.

See it in the project →
Moto

A testing tool that emulates selected AWS service APIs.

Here: The local V1 harness uses Moto for S3 and SQS; those tests do not prove real IAM or AWS networking.

See it in the project →
N+1 query

Loading a list with one query, then issuing another query for each item.

Here: Media’s asset page now joins its own projection in one SELECT; local query-count evidence is not a measured PostgreSQL latency gain.

See it in the project →
NAT / egress

Egress is outbound network traffic. A NAT gateway provides one way for private IPv4 workloads to reach external endpoints.

Here: The baseline avoids a NAT Gateway, using dual-stack Lambda egress and temporary public IPv4 for running Fargate tasks.

See it in the project →
OIDC · OpenID Connect

An identity protocol that lets one system trust a signed identity assertion from another.

Here: GitHub Actions obtains short-lived AWS deployment credentials through OIDC; this is separate from application-user login.

See it in the project →
OpenAPI

A machine-readable description of an HTTP API’s operations, inputs, outputs and security requirements.

Here: Generated Media and Processing documents are the current client contracts; older roadmap examples are historical.

See it in the project →
Outbox / inbox

An outbox records messages that must be sent. An inbox records messages a consumer has already accepted.

Here: Each service commits these records with its own state to handle lost responses, retries and duplicate queue delivery.

See it in the project →
Presigned POST / signed URL

A temporary, signed permission to perform a constrained storage operation.

Here: Upload uses a POST grant with policy fields. Playback uses temporary output access after an owner check; the bucket remains private.

See it in the project →
Repository pattern

A small boundary around persistence operations so callers can express what data they need.

Here: Owner-local repository/query functions keep ownership filtering near reads. This is different from the Git repository that stores the source.

See it in the project →
Ruff / pytest / Vitest

A Python linter/formatter, a Python test framework, and a JavaScript test framework.

Here: They handle different checks. A formatting pass is not a behavior test, and coverage still needs meaningful assertions.

See it in the project →
S3 / PostgreSQL

S3 stores objects such as video bytes. PostgreSQL stores relational application state with transactions and constraints.

Here: The source/output bytes live in S3; ownership, job state, leases and message intentions live in owned SQL databases.

See it in the project →
Smoke test

A focused check that an important path works after a change.

Here: Post-deployment direct upload, terminal status and MP4/HLS playback prove that path for one run, not an entire performance benchmark.

See it in the project →
SNS / AWS Budgets

SNS distributes notifications; Budgets monitors spending against configured thresholds.

Here: Budget notifications are alerts, not a hard cap that prevents further charges.

See it in the project →
SQLAlchemy / ORM

A Python SQL toolkit and object-relational mapper for working with relational databases through Python code.

Here: Mapped models and explicit transactions express owned state, while SQL constraints and locks protect concurrency invariants.

See it in the project →
SQS · Simple Queue Service

AWS’s managed message queue service.

Here: Three standard queues carry commands, work and result snapshots. They can redeliver messages, so consumers must handle duplicates.

See it in the project →
SSM Parameter Store

An AWS store for configuration and protected parameter values.

Here: Exact parameter references provide runtime configuration and credentials; activity flags help avoid unnecessary idle database work.

See it in the project →
State version / tombstone

A state version orders updates. A tombstone records deletion without immediately forgetting the resource existed.

Here: Version checks reject stale results; deletion state prevents a late event from resurrecting an owner-deleted asset.

See it in the project →
TLS / HTTPS

Transport encryption and identity checking; HTTPS is HTTP carried over TLS.

Here: Public requests and database connections use protected transport. Encryption does not replace checking who owns a resource.

See it in the project →
Transaction / invariant

A transaction commits related database changes together. An invariant is a rule that must remain true across allowed changes.

Here: Accepting an asset and staging its processing intent are committed together; an accepted source must have a valid version pin.

See it in the project →
Trivy / ZAP

Trivy scans software packages/images for known issues. ZAP exercises a running web application for security testing.

Here: Exact-image vulnerability gates and bounded authenticated DAST provide different kinds of evidence.

See it in the project →
uv / lockfile

A Python environment/package tool and a recorded dependency resolution used for repeatable installation.

Here: Owner-specific dependency exports share the locked resolution while avoiding unused packages in each image.

See it in the project →
VersionId

An S3 identifier selecting one exact stored version of an object.

Here: The accepted Source descriptor pins it, so rewriting a key does not silently change the source a worker is authorized to process.

See it in the project →
VPC / subnet / security group

An AWS virtual network, a network subdivision, and a set of permitted network traffic rules.

Here: Private Aurora subnets, Lambda egress and Fargate placement must be explained separately from S3 object access policy.
