The project · Level 1

What problem does FlickPond solve in one sentence?
It lets an application turn an owner’s uploaded video into a trackable, playable result through a reusable API, without building its own storage and encoding workflow.

Architecture · Level 1

Why are Job and Attempt separate?
A job describes the requested processing over time. An attempt records one execution. Keeping them separate means a retry can be new work without erasing the failure history or confusing old and new outputs.
Review the explanation →

Architecture · Level 2

Is the Media authorizer a third service?
No. It is a separate execution role running Media code and reading Media’s user records. Service boundaries follow owned rules, data, and release units, not the number of deployed functions.

Architecture · Level 1

What if S3 has no object when finalize runs?

Architecture · Level 2

Does inbox deduplication mean exactly-once processing?
No. It makes repeated delivery of a message ID and body harmless for the domain transaction. Delivery can still repeat, and repair is still needed for the SQL-to-queue gap.

AWS · Level 3

Why did processing take about 37 seconds to start?
The live V2 receipt attributes about 25 seconds to Fargate task startup. The rest includes queueing and launch overhead. A warm pool could reduce this wait, but would add idle task cost; the current design chooses zero idle workers.

AWS · Level 3

Why keep SQL if there is a queue?
SQL holds authoritative jobs, leases and durable send/receive records. SQS transports messages and can redeliver them; it does not replace transactionally owned application state.

Data & recovery · Level 1

What is the difference between retrying a job and receiving a duplicate message?
A legitimate retry creates a new attempt for accepted work. A duplicate message repeats the same transport instruction and should not accidentally create a second logical operation.
Review the explanation →

Data & recovery · Level 1

Why pin a VersionId when the object already has a key?
A key names a location whose contents can change. The version pin selects the exact accepted bytes, so a later write to that key cannot replace the source for an already accepted job.
Review the explanation →

Data & recovery · Level 2

Why is an outbox needed if SQS is already durable?
SQS can preserve a message after it receives it. The outbox protects the earlier gap between committing our database state and successfully sending that message. It stores the intent in the same transaction as the business change.
Review the explanation →

Data & recovery · Level 2

Can we say exactly-once processing?
No. The transport is at-least-once. Inbox identity checks, idempotent state transitions and worker fences aim to preserve one correct logical result despite duplicates; they do not change the delivery guarantee.
Review the explanation →

Data & recovery · Level 2

Why is a queue visibility timeout not enough to protect completion?
It controls message delivery visibility, not ownership of the authoritative job state. A worker can continue running after its message becomes visible again. The SQL attempt and lease fence decides whether that worker may still publish completion.
Review the explanation →

Data & recovery · Level 3

Why not generate a fresh request key after every timeout?
The earlier request may already have committed. A fresh key means a new intention and could submit duplicate work. Reusing the original identity lets the server recognize the uncertain replay.
Review the explanation →

Data & recovery · Level 3

Why not immediately remove every database row when an owner deletes a video?
Some durable state is needed to reject late messages, remember cancellation and finish cleanup after failures. Hiding the resource and recording deletion intent can be safer than forgetting the operation before all external effects are complete.

Security · Level 3

What is the difference between an ECS task role and execution role?
The execution role lets ECS prepare the task, including image pulls and permitted secret injection. The task role supplies AWS permissions to the application inside the running container. Neither is the same as an end user’s login.

The showcase · Level 3

Why split Media and Processing?
