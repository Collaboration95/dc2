## What was measured

component samples below are **controlled PRs with comment-only test-file changes**;
they exercise the actual selected checks but are not natural development traffic or
paired performance benchmarks. Docs adds prose; the negative case deliberately supplies
malformed planning JSON. All five temporary PRs (#167–#171) were closed unmerged.
No runtime behavior, shared branch, or other agent's work was changed by the probes.

Under the new selected policy: docs took 22s; Media tests 2m20s; Processing tests
2m48s; AWS tooling tests 3m52s. The successful component gate median was 168s
(165s excluding initial delay). This demonstrates bounded selected-gate behavior;
it is not a general speedup estimate against different workloads.

The AWS case missed the initial 2–3 minute target. Its required offline lane took
203s: AWS control-plane tests used 149s, CLI skeleton validation 19s, with remaining
setup/lint/operational checks and gate scheduling. Assertions and timeouts were not
weakened. Future tuning should profile that suite if AWS-only feedback needs to be
shorter. Broad source changes that affect inherited runtime or image inputs still
select the corresponding longer checks.

Full verification remains deliberately comprehensive: 462s to its gate, 464s whole
workflow. This run also included forced V1 images and DAST; the earlier baseline
usually skipped V1 images and ran DAST separately. Do not treat these as identical
scopes or claim the complete full suite became faster.

## Durable receipts and agent operation

[receipts-20261017.txt](receipts-20261017.txt) is JSON Lines: one sanitized record per
run, with head SHA, tested SHA where known, event/base/tier, selection, job names,
start/end timestamps, conclusions and metric definitions. Job rows are
`[name, started_at, completed_at, conclusion]`. Baseline tested merge SHAs remain
unknown because those old runs predate selection provenance; their PR head SHAs
are retained separately. New selection records validate run/attempt/event/head
identity before accepting the actual tested SHA.

Use **Dev gate** for an ordinary selected dev PR. React to a failed selected job as
soon as it fails; do not wait for advisory scans or the aggregate before fixing it.
Use **Full verification** for Main promotion, explicit checkpoints and release
acceptance. A selected dev success is not full acceptance. Exact gh commands and
event/path policy are in [policy.md](policy.md) and [measurement.md](measurement.md).
