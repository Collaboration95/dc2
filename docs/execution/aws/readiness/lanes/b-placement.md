## Origin DNS wakeup detail

Auto-assigned EC2 public IPv4 is released on stop; private IPv4 survives the same
instance's stop/start. The new public DNS must be read on each wake, not stored as
permanent CloudFront origin. [EC2 addressing](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using-instance-addressing.html).
Keep the stable distribution hostname as the browser/CLI origin and cookie scope.
Update only the origin domain in its preserved distribution configuration with
optimistic concurrency/ETag; wait until deployed and public smoke passes. Do not
promise an update duration or release success before propagation. A failed update
leaves the environment unavailable and core-hours accruing: show the failure and
close on the session deadline. Keep the origin-header configuration secret during
read/modify/write. Origin settings are documented in [CloudFront origin settings](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/DownloadDistValuesOrigin.html).

State-host **replacement** differs from stop/start: reattach the retained data disk
and update private DSN/Redis host configuration if private address changes. This
maintenance can require refreshing both services' configuration; it is not proof
of independent Processing-only deployment. No EIP or paid stable origin service is
needed for the accepted slower warmup.
