## Small future cloud acceptance — actual results required

This is a proposed protocol, not an executed command or a PASS. Use six long fixture submissions **total**, plus short workflow jobs; track cumulative bytes and worker-task time before each phase. Use the same 60-second source file and reuse completed assets. Invalid tiny content can test rejection; a new 101-MiB upload would consume much of the cloud allowance, so retain existing local oversized-upload evidence and inspect cloud limit configuration unless an explicit bounded cloud-limit check is required.

1. **Preconditions/provenance:** explicit approved account/region/window/plan, source SHA/clean state, actual task-definition revisions/digests/roles, health/config hash excluding secrets, fixture SHA/size/duration, CPU/memory/task/container limits, public edge origin and test scope. 2. **Public workflow:** normal-trust CloudFront browser session plus independent Publisher with private jar.
